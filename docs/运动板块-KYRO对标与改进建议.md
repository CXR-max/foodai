# 运动板块 · KYRO 对标与改进建议

> 对标对象：韩国 Movements Lab 的 **KYRO（키로）**，2026 年 1 月上线，日韩合计 10 万+ 跑者（官方口径）。
> 对照对象：我们现在的领地跑 MVP（25m 栅格 + SVG 轮廓 + 面积衰减 + 好友切地 + 领地详情）。
> 结论先行：**KYRO 的核心不是“记录跑步”，而是“把城市地图变成可争夺的公共画布”**。我们已经有圈地、衰减、好友切地，差距主要在 **闭环判定太严、内场填得太保守、没有成长线/跑团/地标/激战区**。不建议全抄，尤其不要照抄“超大圈”和“陌生人随便抢”。

---

## 1. KYRO 的规则到底怎么定

### 1.1 圈地：官方自己有两套说法

KYRO 的圈地规则，商店说明和官网 FAQ 不完全一致，这是公开可查的事实：

| 来源 | 说法 |
|---|---|
| App Store 商店说明 | 轨迹**自身交叉**即可成环，**不必回到起点**，没有距离门槛 |
| 官网 FAQ（更严格） | 起点与终点相距 **50m 以内**；围出的形状**宽度至少 20m**；暂停后在远处重新开跑导致轨迹断线则不算 |
| 官网首页 | “You don't have to finish exactly where you started. Run around an area and KYRO turns the inside into your territory.” |

稳妥的跑法是按严格版：**收拢闭环、跑宽形状、轨迹不断线**——两套规则下都成立。
不变的一点：**一条原路折返的直线，跑多远都圈不到地**；决定收益的是围出的**面积**，不是公里数。

> 对我们的启发：我们现在的闭环条件是“首尾 30m 内 + 轨迹 ≥300m + 跑步 ≥600m/6min”，比 KYRO 严格版还严。**400m 操场跑一圈（400m、3–5 分钟）在我们这里会被“不足 600 米”直接判掉**——这是个必须优先修的 bug，不是玩法差异。

### 1.2 抢地、防守、成长、社交

| 能力 | KYRO 的公开规则/功能 |
|---|---|
| 抢地 | 别人跑进你的领地就能夺走；你也可以再跑回来 |
| 防守/复仇 | 叫上 crew（跑团）一起把地抢回来 |
| 段位 | XP 累积，13 段位：Iron → Legend |
| 连跑 | 以“周”为单位的 streak |
| 跑团 | Clubs / crew，按团队累积里程、比拼贡献、集体抢地 |
| 地标 | Landmarks：官方标记的人气路线，自动计圈，有独立排行榜 |
| 路线 | Courses：跑者常跑的路线成为 course，可分享、可跑别人的路线 |
| 地图 | 主页/地图/记录都在地图上；“激战区”看当前最热街区 |
| 排行榜 | 领地面积、距离，按大区域和附近分别排 |
| 记录 | GPS 路线/距离/配速/步频/分段；支持离线记录、联网同步；每次跑步可设可见范围 |
| 设备 | Apple Watch、Garmin、Suunto 同步 |
| 付费 | 免费为主；Heatmap、3D Replay 等属于 KYRO PRO |
| 隐私 | 单次跑步可设可见范围；通知可接收领地变化/排行/挑战提醒 |

### 1.3 它真正留住人的四件事

1. **圈地结果可视化**：跑完立刻看到“这块地是我的”，比配速表更有情绪。
2. **抢地/防守**：地会被拿走，也能抢回来，形成“明天还得去”的理由。
3. **成长线**：XP + 13 段位 + 周 streak，跑量不再是唯一进度条。
4. **跑团/地标/路线**：把一个人的跑步变成一群人的长期对抗。

## 3. 五个最关键的差距

### 差距 1：闭环判定太严，连 400m 操场都圈不了

- 我们：`30m 首尾 + ≥300m + ≥600m/6min`。
- KYRO：FAQ 只要求 `50m + 宽 20m + 不断线`；商店甚至允许“自交即可、不必回起点”。
- 后果：**跑一圈操场（400m）在我们这里不产生领地**；用户会觉得“我跑了，怎么没地”。
- 建议：领地判定与“运动记录”解耦：
  - 记录门槛保持 3 分钟 / 150m 左右即可；
  - 圈地门槛改为 **首尾 ≤50m 或轨迹自交** + **形状宽度 ≥20m** + **轨迹不断线**；
  - 不再用 600m/6min 作为圈地硬门槛；
  - 400m 操场一圈必须能圈。

### 差距 2：内场填得太保守，大圈变成“空心/带状”

- 我们：内场每格离轨迹 ≤60m，超过就不填；所以 2km 大圈只亮一条边，看起来像空心。
- KYRO：闭环内部整片归你（官网示例 8.1km 路线 +3.73km²）。
- 后果：用户说“我想要的是线里面整片是领地”，我们的 60m 规则正好相反。
- 建议：
  - **小/中圈：整个内部填充**；
  - 用**面积上限**而不是“离轨迹 60m”来控制平衡：单次最多 0.08km²（8 万㎡，约 128 个 25m 格），超过则提示“这个圈太大，只能占边缘/请跑小一点”；
  - 这样 400m 操场（约 0.7 万㎡）能整片填，2km 校园圈（约 25 万㎡）被拦下，不会一圈吞校。

### 差距 3：只有好友，没有“跑团/crew”

- KYRO 的抢地快感来自 **crew 集体抢回**：一个人被抢，群里喊人，周末一起去跑。
- 我们现在只有好友/关注，没有团队目标、没有贡献榜。
- 建议：
  - 增加 **跑团**（≤10 人，邀请码加入）；
  - 团队领地 = 成员领地并集（只用于展示和团队榜，产权仍归个人，避免衰减/退队纠纷）；
  - 团队周榜：并集面积、团队切地数、团队地标；
  - 成员贡献 = 本周新拓 + 切地 + 助跑；
  - 团队内不能互抢，可以“助跑”回血。

### 差距 4：没有 XP/段位/周 streak，缺少长期成长线

- 我们现在只有积分、徽章、打卡连续；领地本身没有等级。
- KYRO：XP + 13 段位（Iron → Legend）+ 周 streak。
- 建议：
  - 做 **10 级“领地段位”**（不必照抄 13 级）：散步者 → 跑者 → 街区主 → 城主 → 传奇；
  - XP 来源：有效跑步距离（1 XP/100m）+ 新占面积（1 XP/100㎡）+ 切地/夺回奖励；
  - 周 streak：每周至少 1 次有效领地跑；断签只重置 streak，不掉地；
  - 段位只发称号/徽章，不直接加战力，避免滚雪球。

### 差距 5：地图只有“静态领地”，没有“激战区/地标/路线”

- KYRO 的地图会告诉你“现在哪条街最热”“哪个地标有人在刷圈”。
- 我们现在只有色块和面积标签，用户不知道“去哪抢”。
- 建议：
  - **激战区**：过去 7 天易主 ≥3 次的格子/区域，红色脉冲；点进去看“谁和谁在抢”；
  - **地标**：操场、食堂前广场、江边步道 3 个；地标内自动计圈、独立排行榜、面积 ×2；
  - **路线**：把常跑的闭环存成 course，显示距离/预计时间/可圈面积，支持分享；
  - **领地战报**：周结算海报 + 本周扩张/被抢/夺回。

## 4. 改进方案（按优先级）

### P0：先把“跑一圈就能圈地”做对（1–2 天）

1. **圈地判定与运动门槛解耦**：
   - 运动记录：≥3 分钟、≥150m（防原地）；
   - 圈地：首尾 ≤50m **或** 轨迹自交；宽度 ≥20m；轨迹不断线；
   - 去掉 600m/6min 的圈地硬门槛。
2. **内场整片填充**：
   - 小/中圈全填；
   - 单次面积上限 0.08km²（或 120 格）；
   - 超过上限给出明确提示，不再默默只填 60m 边。
3. **前端显示真实闭环**：
   - 跑动中检测到闭环时，实时显示“已闭合，预计圈 X㎡”；
   - 结束后展示“本次圈下 X㎡ / 切走 Y㎡”，并可直接跳到领地详情。
4. **修复 400m 操场**：一圈必须能圈；这是最容易被用户发现的 bug。

### P1：把“一个人圈地”变成“一群人抢地”（1–2 周）

1. **跑团/crew**：
   - 10 人、邀请码、团队并集面积、团队周榜、成员贡献；
   - 团队内免伤 + 助跑；退团 7 天冷却。
2. **激战区**：
   - 7 天易主 ≥3 次 → 红色脉冲；地图顶部“激战区”入口；
   - 点击看最近争夺记录，支持“去抢回”。
3. **地标/路线**：
   - 3 个校园地标；自动计圈；地标榜；面积 ×2；
   - 常跑路线存为 course，显示距离/预计时间/可圈面积。
4. **成长线**：
   - 10 级段位 + XP + 周 streak；
   - 本地/附近/好友三个榜单。

### P2：把“地图”做成内容（2–4 周）

1. 领地战报/分享海报；跑步轨迹回放。
2. 周结算 + 赛季 + 徽章。
3. 单次跑步可见范围（公开/好友/私密）、家附近模糊区。
4. 离线记录/GPX 导入/手表同步（Web 做不了，等 App）。
5. PRO：热力图/回放/路线规划（可选，课程项目不必）。

## 5. 不建议照抄的地方

| KYRO 做法 | 为什么不建议直接抄 |
|---|---|
| 单次 +3.73km² 的超大圈 | 校园/城市小范围会被一个人吞掉；我们保留面积上限 |
| 商店版的“自交即可、不必回起点” | 太宽松会被“绕 8 字/原地小圈”刷；我们用“50m 或自交 + 宽 20m + 不断线”的折中 |
| 任何人都能抢 | 陌生人骚扰、作弊、报复成本高；我们先做好友/跑团互抢，公开赛作为可选 |
| 13 段位 Iron→Legend | 名称和层级不是关键；10 级中文段位更适合我们的用户 |
| 手表/离线/PRO | 我们是 Web，短期做不了；先把核心圈地体验做好 |
| Arena 品牌挑战 | 需要商务合作；课程项目不做 |

## 10. 已落地的 P0（2026-11-25）

- 闭环：**首尾 ≤50m 或轨迹自交**（lollipop 不回到总起点也能圈），不再强制 300m/600m。
- 运动门槛：**90 秒 / 150m**；400m 操场一圈已实测能圈（28 格 ≈ 1.75 万㎡）。
- 内场：**整片填充**，单次上限 **128 格 ≈ 0.08km²**；超过会提示“圈太大”。
- 跑步中：显示“闭环已形成，预计圈下 X㎡”或“还差 Xm 回到起点”。
- 地图：去掉最近轨迹的绿色小圈；头像点缩小，放大到 17 级才显示昵称。
- 领地详情：面积、最近占领记录（距离/时长/配速/消耗）、被抢动态、**抢回去**按钮。
- 好友：6 个（小北无领地），陌生人只能看；好友可以互切。

## 11. 领地详情页重构（2026-11-25 晚）

半屏 sheet 换成独立整页 `/territory/owner/:id`，点地块/好友直接跳转。

**页面结构**：形状剪影图腾 + 面积 → 活力条（消退倒计时、活力分布）→ 交锋战绩 + 战书倒计时 → 最近占领 → 动态时间线 → 底部动作栏。

**新增能力**：

- `territory_challenges` 表：24 小时异步约战，到期按「是否真的切走对方的地」结算胜负，不动格子归属。
- `GET /territory/owners/{id}` 增补 `cells`（形状还原）、`cells_total`、`vitality_avg`、`days_left`、`held_days`、`record`（我与 TA 的交锋场次）、`challenge`。
- `POST /territory/challenges` 下战书（仅好友）、`POST /territory/challenges/{id}/accept` 应战。
- 详情页底部动作按关系分流：自己=去巩固；好友=下战书/直接去抢；被下战书=应战；陌生人=加好友。

**顺带**：格子→轮廓算法抽到 `frontend/src/utils/territoryShape.ts`，地图页与详情页共用；剪影渲染时填掉内圈空洞，避免看起来像破图。

## 12. 结算 / 段位 / 无主地 / 地图可读性（2026-11-25 二）

**一、跑完整屏结算** `/territory/settle/:workoutId`

跑完保存后，若本次真的记到地，直接进结算页（否则回运动报告）。内容：面积滚动 + 本场形状 + 距离/时长/配速 + 新增/切走/巩固/磨活力四格 + 从谁手里切走 + 段位进度 + 排名差距 + 排行榜前三 + 下一步动作。

- 后端 `GET /territory/runs/{id}` 改为返回 `settlement()`：在原 run 数据上补 `area_total_m2`、`victims`（按受害者的格子数与面积）、`tier`、`rank/rank_of`、`ahead_name/ahead_gap_m2`、`recapture_cells`。
- 排名给「差距」而不是只给名次：`rank_gap()` 同时返回上一名的名字和差多少㎡。
- 结算页顺手接上了写好却一直没人调的 `/territory/leaderboard`。

**二、段位**：`TIERS`（刚起步 / 街角跑者 / 操场常客 / 街区领主 / 校园霸主）+ `tier_of(area)`，返回当前段位、下一段位、进度、还差多少。地图片统计卡、领地详情、结算页三处都显示。

**三、无主地**：`map_cells` 额外返回 `neutral`（`owner_id` 为空但 `prev_owner_id` 存在的格子 = 衰退或释放掉的地）。地图上画灰色虚线幽灵轮廓，聚到 6 格以上标「无主地 N 格 · 跑进去就归你」，点一下弹认领提示。只在「全部」视野出现，筛选好友/自己时不混进来。

**四、活力条与消退倒计时**：`me()` 补 `vitality_avg / days_left / tier / rank_of / ahead_name / ahead_gap_m2 / recapture_cells`。地图页统计卡显示活力条 +「约 N 天后消退」+ 段位 +「这片你占 X%」。

**五、48h 夺回徽标**：`map_cells` 对 `prev_owner_id == 我 && stolen_at < 48h` 的格子打 flags 第 2 位，并返回 `recapture: [key, 剩余秒数]`。前端画橙色虚线 + 徽标「夺回伤害 ×2 · 还剩 45 小时」，每分钟刷新倒计时。

**六、图例**：底部「图例」按钮 → 面板解释六件事：颜色深浅=活力、我的地、好友、附近的人、可夺回、无主地。

**七、取消 15 分钟延迟**：`OWNER_DELAY_MIN = 15 → 0`。地图本来就不返回轨迹，延迟唯一的效果是「被抢了当场看不见」，与 48h 夺回倒计时直接冲突。

**顺带修的 bug**：
- 顶部浮层原来每块都写死 `top`（58/96/166px），统计卡多一行就会盖住事件条；改成 `.hud` 流式列布局。
- 「无主地」「夺回」徽标重复做了一次 WGS→GCJ 纠偏（坐标已是 GCJ），导致标签被甩到屏幕外。
- `me()` 返回的 `color` 没用 `pref.color`，导致图例色块和地图上自己的颜色不一致。

## 13. 「夺回伤害 ×2」改为「↺45h」（2026-11-25 三）

**为什么原来的说法是错的**

代码里 `ATTACK_BASE = 45`、`ATTACK_RECAPTURE = 90`，而一块刚被抢走的地 `NEW_OWNER_VITALITY = 55`。
真实含义是：平时擦着地边跑一次磨 45 点，磨不穿 55，**要两趟**；被抢后 48h 内跑回去一次磨 90，**一趟就够**。

玩家看不到 45 这个基准，所以「×2」是个没有参照物的数字。而且这个倍数只在「轨迹压过边界」时生效，
闭环圈地是直接翻转归属（`is_fill` 分支），跟倍数无关——大部分玩家遇不到这个场景，却要在地图上读到一句游戏黑话。

**改法**

- 地图上只留 `↺45h`：挂在轮廓东北角外侧，9px 白底小纸片、无阴影、不压地块和昵称。数字是剩余小时。
- 文案统一换成「更容易拿回来」，全项目清掉「伤害」二字（地图统计卡、事件条、引导页、图例、结算页 ×3、详情页）。
- 图例里做一个同款小样（橙色虚线框 + 右下 ↺45h），让地图符号能对上号。
- 顺手修：`↺45h` 图例小样因父容器非 flex 导致 `.lg-dash` 退化成细竖线。

**如果以后要重做这块，方向是**：倒计时不该只是装饰，应该可点——点一下跳到那块地并高亮，或者生成「去抢回来」的一条路线。

## 14. 领地跑功能演示视频（2026-11-25 三）

**为什么不用 AI 生成视频**：AI 文生视频会虚构界面，和产品对不上，不能当产品演示用。演示必须是真实页面。

**做法**：浏览器内逐帧渲染 → ffmpeg 编码，全程不依赖手工录屏，可重复生成。

1. `scripts/video_grab.cjs`：puppeteer 手机视口（390 宽 @3x）抓真实页面截图。
   详情/结算是全屏固定容器，`fullPage` 无效，改用更高视口（1180/1000）让内容一次展开。
2. `.tmp_video/video.html`：1920x1080 演示版式。左手机 + 右讲解，7 个镜头（封面 / 地图 / 图例 / 详情 / 下战书 / 结算 / 收尾）。
   所有动效由 `window.seek(t)` 手算，不依赖 CSS 动画时序——这样逐帧截图与实时播放完全一致，不会掉帧。
3. `frontend/_render2.cjs`：3 个页面并行 + CDP `Page.captureScreenshot`，980 帧约 47 秒（`page.screenshot` 1.3s/帧，慢 27 倍）。
4. ffmpeg-static（npm 走 npmmirror + `--strict-ssl=false` 才装得上）编码 H.264。

**踩到的坑**
- 下战书镜头原本用放大裁切，把左右内容切掉了；改成聚光灯（`box-shadow: 0 0 0 9999px` 挖孔）只圈住「战书中」那一条。
- 页脚数字页码与章节号是两套编号（04/07 vs 03 详情），改成进度点。
- 详情页滚动开始过早导致导航栏被滚出视野，改为前 2.6 秒静止、后段再滚。
- 收尾镜头没有配图，手机露成一块白板，改成继续显示地图并轻微淡化。

**重新生成视频的完整步骤**（改了 UI 之后照着跑一遍即可）

```bash
cd backend && TOKEN=$(../backend/.venv/Scripts/python.exe -c "from app.core.security import create_token; print(create_token(6))")
cd ../scripts
node video_grab.cjs "$TOKEN"      # 1. 抓真实页面截图 -> .tmp_video/shots
python video_trim.py              # 2. 裁掉长页底部空白 -> *_tall.png
node video_render.cjs             # 3. 逐帧渲染 -> .tmp_video/frames（约 1~10 分钟）
cd .. && frontend/node_modules/ffmpeg-static/ffmpeg.exe -y -framerate 25 \
  -i .tmp_video/frames/%05d.jpg -c:v libx264 -pix_fmt yuv420p -crf 19 \
  -movflags +faststart docs/领地跑-功能演示.mp4   # 4. 编码
```

版式与文案都在 `scripts/video_layout.html`（改 `SCENES` 数组即可增删镜头）。
