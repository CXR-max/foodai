# 计划模块 v2 改动说明

> 范围：计划生成 → 目标下发 → 沿用/历史 → 导入日程 → 睡眠/饮水打卡 → 每日汇总。
> 手环数据接入本次未做，只预留了字段和写入通道。

## 一、这次做了什么

| # | 能力 | 说明 |
|---|---|---|
| 1 | 目标体系 | 每天算出热量上下限、蛋白下限、脂肪/碳水区间、纤维、糖、钠、饮水下限、睡眠下限、运动消耗下限，存 `diet_plans.targets` |
| 2 | 运动处方 | 从「每天 +5 分钟」改成按每周训练天数排课：训练日主项 + 拉伸、恢复日低强度，强度按周递进 |
| 3 | 睡眠方案 | 按用户作息给出入睡/起床时间、目标时长和建议；日程据此生成睡眠任务 |
| 4 | 历史与沿用 | 计划列表卡片（天数/日均热量/运动总消耗）→ 点进详情 → 「沿用这周」顺延一周，支持原样复制或重算餐食 |
| 5 | 导入日程 | 「导入日历」改名「导入日程」，支持单天和整周；任务新增睡眠、饮水两类 |
| 6 | 睡眠 / 饮水打卡 | 新表 `sleep_logs`、`water_logs`，记录达标后自动把日程任务置为完成并发积分 |
| 7 | 打卡日历 | 月历每天显示「已完成/总任务」、是否覆盖方案，点某天可切到那天看任务 |
| 8 | 每日汇总 | `GET /api/day/summary` 一次返回目标、摄入、消耗、饮水、睡眠、任务进度，日程和「我的」共用 |

## 二、目标口径（可直接写进论文/答辩）

| 指标 | 算法 |
|---|---|
| 热量区间 | 目标值 ×（−10% ~ +5%），下限不低于 BMR × 1.1 |
| 蛋白下限 | 减脂 1.6 / 维持 1.2 / 增肌 1.8 g/kg |
| 脂肪 | 总热量 20%~30% |
| 碳水 | 剩余热量（按 45%~55% 折算） |
| 膳食纤维 | 25 g（《中国居民膳食指南 2022》：25~30 g） |
| 添加糖 | < 25 g |
| 钠 | < 2000 mg（约食盐 5 g） |
| 饮水 | 体重 × 30 ml，不低于 1500 ml（有自定义值优先） |
| 睡眠 | 7~9 小时，达标线取下限的 90% |
| 运动消耗下限 | 减脂按热量缺口的 50% 估，夹在 150~400 kcal；恢复日取下限的 30% |

> 注意：营养库 108 条菜品里约四成有 `fiber_g`，钠/糖覆盖率相近且缺失值按 0 处理，
> 所以求解器只对纤维做低权重软引导，钠和糖作为**监测目标**展示，不做硬约束——否则会
> 系统性地偏向「没录数据」的菜品，反而失真。

## 三、数据模型

| 表 | 新增字段 |
|---|---|
| `diet_plans` | `targets`、`reused_from`、`plan_version` |
| `plan_days` | `exercises`（多条）、`sleep`、`water_ml`、`targets`（当日覆盖） |
| `health_profiles` | `sleep_time`、`wake_time`、`water_target_ml` |
| `sleep_logs`（新） | 一晚一条：入睡/起床/时长/深睡/质量/来源（manual、device、manual_override） |
| `water_logs`（新） | 一天多条：每次毫升数 |

兼容：`plan_days.exercise` 保留为「主项」，读接口在没有 `exercises` 时自动包成一条，老方案不报错。

## 四、接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/plans` | 列表（含天数、日均热量、运动总消耗、结束日期） |
| GET | `/api/plans/{id}` | 详情（含每日运动/睡眠/目标） |
| GET | `/api/plans/active?date=` | 当天方案天 + 当日目标 |
| POST | `/api/plans/{id}/reuse` | 沿用：`{mode: copy｜reframe, start_date?}` |
| POST | `/api/plans/{id}/import` | 导入日程：`{mode: day｜week, day_index?}` |
| PUT | `/api/plans/{id}/days/{i}` | 改餐食 / 运动 / 睡眠 / 饮水 / 当日目标 |
| POST | `/api/sleep` | 记录一晚睡眠（自动同步打卡） |
| GET | `/api/sleep?date=` / `?days=7` | 单日 / 最近 N 晚 |
| POST | `/api/water` | 加一次饮水 |
| GET | `/api/water?date=` | 当日累计与目标 |
| GET | `/api/day/summary?date=` | 每日汇总 |
| GET | `/api/check-ins?month=` | 月历（新增 `has_plan`、`pct`、`plan_id`） |

## 五、打卡链路

```
计划生成 → plan_days 带 targets/sleep/water_ml
   ↓ 导入日程
check_ins 生成 7 类任务（四餐 + 运动 + 睡眠 + 饮水）
   ↓ 用户操作
食物记录 / 运动打卡 / 睡眠记录 / 饮水累计
   ↓ 达标
sleep、water 自动置 done 并发积分；餐食、运动点「打卡」完成
   ↓
/day/summary 汇总 → 日程顶部、我的页
```

## 六、已知限制

1. 云端模型给的份量常常明显低于目标（实测 1 天 760 kcal，目标 2000），现在会在偏离超过 15% 时用本地求解器重排当天餐食，并在 `targets.calorie_source` 标注 `solver_calibrated`。
2. 睡眠记录的手环通道（`source=device`）已通，但**没有导入器**，本版只有手动。
3. 运动处方只按周次递进，没有根据实际完成率动态调整（后续可接 `check_ins` 完成率）。
4. 钠/糖目前只做展示，不做求解约束（原因见第二节）。
