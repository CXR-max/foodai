# Keep 运动记录板块拆解（用于我们自己的运动模块设计）

> 用途：作为 `workouts` 模块的设计依据。不涉及 UI 视觉，只拆「用户做什么 / 系统记什么 / 数据怎么流」。

---

## 0. 核心认知

「选择运动类型」在 Keep 里**不是一个下拉框，而是选择一套数据采集规则**。
选「户外跑步」意味着：开 GPS、按公里分段、算配速、有轨迹、有海拔；
选「跳绳」意味着：不开 GPS、按次数计、没有轨迹、没有配速。
所以类型是「采集策略」的开关，后面所有字段、页面、校验都由它决定。

---

## 1. 入口层级

```
底部 tab「运动」（部分版本从首页「跑步」图标直达）
  └─ 运动首页
       ├─ 顶部：今日/本周数据（次数、里程、时长、消耗）
       ├─ 中部：运动类型横排（户外跑步 / 骑行 / 行走 / 室内跑步机 / 跳绳 / 训练课程）
       ├─ 地图卡：常跑路线、附近路线推荐
       ├─ 下方：运动历史入口、训练计划
       └─ 点任一类型 → 该类型的「准备页」→ 运动中页 → 运动报告页
  └─ 运动历史 → 列表 / 筛选 / 单次详情（= 报告页去掉分享）
```

关键：点类型**不弹选择框**，直接进该类型的准备页。多一层选择就会掉开始率。

---

## 2. 运动类型的三档分类（这是设计的骨架）

| 档 | 包含 | 数据来源 | 有没有轨迹 | 核心指标 |
|---|---|---|---|---|
| A 户外定位类 | 户外跑步、骑行、行走、登山徒步 | GPS | 有 | 距离、配速/均速、海拔 |
| B 室内计量类 | 室内跑步（跑步机）、跳绳、划船机、椭圆机 | 传感器计步/计数，或手动输入 | 无 | 时长、次数/距离（手填） |
| C 内容跟练类 | 瑜伽、HIIT、力量、操课、拉伸、冥想 | 课程完成度 | 无 | 完成动作数、时长、消耗（课程预设） |
| D 手动/第三方 | 游泳、球类、手环同步 | 用户手填或设备同步 | 无 | 时长、消耗 |

**我们的取舍**：先做 A 档的跑步 + 行走，B/C 档用「手动补录」兜住，不追求全。

---

## 3. 完整流程（以户外跑步为例，6 个阶段）

### 阶段 1｜准备（Pre）

进入后不需要点「开始」，先自动做四件事：

1. **搜星**：申请定位权限 → 显示「正在定位…」→ 拿到精度 ±5m 的点才允许开始；失败给降级入口「仅记录时长（无轨迹）」
2. **选模式**（Keep 有三种，我们做前两种就够）
   - 自由跑：无目标
   - 目标跑：目标距离（3/5/10km）或目标时长（20/30/60min），过程中进度环 + 到点语音提示
   - 燃脂跑 / 间歇跑：走跑交替，按节拍语音引导（我们 v2 再做）
3. **改设置**：语音播报频率、音乐、屏幕常亮、自动暂停（配速低于阈值 30s 自动暂停）
4. **3-2-1 倒计时** → 进入运动中。倒计时是必须的，否则用户点了手机还没塞进口袋就开始计时

### 阶段 2｜运动中（Recording）——真正的难点都在这里

界面三层：
- **地图层**：实时画轨迹，按配速分段着色（快/正常/慢三色），起终点图标
- **主数据层**：超大数字显示 距离 / 时长 / 当前配速；左右滑切换第二屏（心率、步频、步幅、海拔、累计爬升）
- **操作层**：暂停/继续、**长按结束**（防误触）、音乐浮窗

后台在跑的逻辑（实现时必须都有，否则数据不可信）：

1. **采样**：高精度定位，约 1 秒 1 点
2. **点过滤**（不做过虑的数据是垃圾）：
   - `accuracy > 30m` 丢弃
   - 与上一个有效点距离 `< 3~5m` 丢弃（站着不动时的抖动）
   - 由两点算出速度 `> 12m/s`（跑步不可能）判为漂移丢弃
3. **距离累加**：相邻点 haversine 求和；**暂停期间不累加**
4. **分段**：每满 1km 落一个 split（该公里用时、配速、海拔变化）
5. **当前配速**：滑动窗口（近 200~500m）计算，不能用「总距离/总时间」，否则刚起步会显示一个荒谬的数
6. **语音播报**：每公里一次 + 每 5 分钟一次，模板「已完成 3 公里，用时 18 分 20 秒，平均配速 6 分 07 秒」
7. **断网/后台**：轨迹先写本地（IndexedDB），结束后再 POST；无网也能记录
8. **异常兜底**：定位丢失 > 30s 弹提示；切后台回来要能续上；来电中断要能恢复

### 阶段 3｜结束与保存（Finish）

1. 长按结束 → 二次确认 → 计时停止
2. **保存前校验**：距离 < 100m 或时长 < 1min → 提示「本次运动太短，是否保存」
3. **补三个字段**：运动感受（轻松/适中/吃力，这个正好能喂给我们现有的 MET 强度修正）、天气（可选）、配图/文字
4. **上传**：轨迹点数组 + 汇总值一起提交；**服务端重算距离/配速/消耗**，不信任前端

### 阶段 4｜运动报告（Report）——最值钱的一屏

四块内容，从上到下：

1. **头图**：轨迹地图缩略图 + 起终点标记 + 四个大数字（距离 / 时长 / 平均配速 / 消耗）
2. **数据网格**：最快公里配速、平均步频、步幅、累计爬升、平均心率、最大心率
3. **图表**：配速曲线（按公里）、心率区间分布（五区）、海拔曲线
4. **对比**：和自己上次同类型比、和自己的平均比（Keep 还用「同城同龄」做社交比较）

底部动作：生成带轨迹水印的海报 → 分享到社区/朋友圈、导出 GPX、**同步为一条运动记录**（这是它和打卡、成就、挑战的接口）。

### 阶段 5｜沉淀（History & Stats）

- **列表**：按时间倒序，卡片 = 类型图标 + 日期 + 距离 + 时长 + 配速；按类型筛选 tab
- **汇总**：周/月/年三档 —— 总里程、出勤天数、平均配速趋势、总消耗
- **日历**：有运动的日子打点（和我们打卡页的月历同构，可复用）
- **单次详情**：就是报告页，去掉分享按钮

### 阶段 6｜联动（闭环，别漏）

| 联动对象 | 行为 |
|---|---|
| 打卡 | 运动记录保存后，自动把当天 `exercise` 任务置为 done，不用再手填 |
| 积分 | 按现有规则给分（首次 +2，任务 +3），**注意防刷：同一天多次只算一次任务分** |
| 成就 | 首次跑步、单次 5km、累计 100km、连续 7 天、最快配速 PB |
| 挑战赛 | 周里程挑战从 workouts 汇总进度 |
| 社区 | 一键发动态，带轨迹水印 |
| 饮食 | 消耗回填到「今日热量预算」，形成摄入-消耗缺口（我们已有 budget 组件） |
| 训练计划 | 今天的计划是「轻松跑 3km」，跑完自动勾掉 |

## 4. 字段矩阵（按类型）

| 类型 | 必填 | GPS | 核心指标 | 次要指标 | 分段 | 海拔 |
|---|---|---|---|---|---|---|
| 户外跑步 | 距离、时长、平均配速 | 是 | 配速、距离 | 步频、步幅、心率 | 每 1km | 有 |
| 骑行 | 距离、时长、均速、最高速 | 是 | 速度、里程 | 踏频、功率、累计爬升 | 每 5km | 有 |
| 行走 | 距离、时长、步数 | 是 | 距离、步数 | 配速 | 每 1km | 可选 |
| 室内跑步机 | 距离、时长 | 否 | 距离、配速 | 坡度、心率 | 可选 | 无 |
| 跳绳 | 个数、时长 | 否 | 次数、频率 | 中断次数 | 无 | 无 |
| 跟练课程 | 动作数、时长 | 否 | 消耗 | 完成度 | 按动作 | 无 |

## 5. 状态机（实现时必须抽象）

```
idle → preparing（定位中）→ running ⇄ paused → finishing → saved | discarded
```

规则：
- 只有 `running` 能暂停，只有 `paused`/'running' 能结束
- 计时器**不能用 `Date.now() - startTime`**（暂停会继续走），要用累加的运行毫秒数
- 离开页面（`beforeunload`）要拦截；中途崩溃要能从本地草稿恢复
- 「保存中」要防重复提交（幂等键）

## 6. 我们的落地方案（分三版）

### MVP（3~4 天，能演示）
- 只做户外跑步 + 行走
- 无目标模式，只有 开始 / 暂停 / 结束
- 地图画单色 polyline，实时显示 距离 / 时长 / 配速
- 报告页：距离、时长、平均配速、消耗 + 轨迹图
- 后端 `workouts` 表 + 3 个接口（POST 上传 / GET 列表 / GET 详情）

### V1（+1 周，像样）
- 目标跑、自动暂停、每公里分段、语音播报（`speechSynthesis`，零成本）
- 运动历史列表 + 周月统计 + 日历打点
- 保存后自动完成打卡任务 + 触发成就
- 分享海报（复用现有 `SharePosterDialog`，加轨迹底图）

### V2（可选，加分）
- 骑行（均速/爬升）、室内跑（手动输入）
- 常跑路线 / 附近路线
- 心率区间（无硬件就标「未接入」）

## 7. 容易踩的坑

1. **Web 拿不到后台定位**：原生 App 才能后台持续定位；浏览器切后台会被限流甚至断掉。必须 WakeLock + 「请保持页面在前台」提示，答辩时要主动说明这一点（也正好论证「后续是否做小程序/App 壳」）。
2. **室内跑不能依赖 GPS**：必须有「无轨迹模式」，否则在教室里演示直接失败。
3. **距离算法别只放前端**：否则会出现「我手机显示 5.02km，你后台 4.87km」，服务端统一重算。
4. **消耗不要用距离换算**：仍走我们现有的 MET × 体重 × 时长 + 性别/年龄/体脂修正，把「配速」作为一个修正系数接进去，这是我们比 Keep 更能讲清的地方（我们有逐层系数展示）。
5. **轨迹点会撑大 SQLite**：1 小时 ≈ 3600 点。做 Douglas-Peucker 抽稀（或每 3~5 秒保留一点），压到 600~800 点、约 30KB，单条记录可接受；展示用抽稀点，汇总用原始累加值。
6. **别做「实时上传」**：运动中以 1 秒 1 次 POST 会打爆接口，必须结束后一次性提交 + 本地草稿。
