# 运动模块 · 地图与定位技术方案

> 范围：只讨论运动模块本身——地图、定位、轨迹、录制、报告。不涉及与其他板块的联动。
> 结论先行：**地图不用换；先修 6 个"看起来像地图问题、其实是代码问题"的 bug。定位精度靠采样/滤波/自动暂停，不靠换 SDK。**

---

## 0. 直接回答：自绘 vs 高德/百度

### 0.1 你现在到底是什么方案

- **底图**：高德栅格瓦片（`webrd0{s}.is.autonavi.com`），由 Leaflet 的 `TileLayer` 加载。
- **轨迹**：Leaflet `Polyline`，开了 `preferCanvas: true`，线是 Canvas 画的。
- **坐标**：手机给 WGS-84，渲染前转 GCJ-02。
- **兜底**：瓦片连续失败且一张没成功 → 底图退化成网格，轨迹照画。

所以准确说法不是"自绘地图"，而是：**Leaflet 承载高德瓦片底图 + 自绘轨迹线**。底图不是你们画的，路线是你们画的。

> ⚠️ 汇报口径要注意：你们的话术里说"接入高德瓦片，用 Canvas 一层层拼出来"，但代码里底图是 Leaflet 的 `<img>` 瓦片，只有轨迹线走 Canvas。被追问"你的瓦片拼接代码在哪"会对不上。
> 建议改成：**"底图用高德栅格瓦片，Leaflet 承载；轨迹用 Canvas 渲染；没引官方 SDK 是为了免 key、免域名绑定、首屏更小；瓦片失败降级网格。"** 这段话同样有技术含量，而且是真的。

### 0.2 换 SDK 能解决什么、不能解决什么

| 换高德/百度 JS SDK | 能解决 | 不能解决 |
|---|---|---|
| 底图 | 矢量地图、缩放更平滑、样式更干净、支持夜间模式 | 瓦片加载慢/断网（SDK 也会白屏） |
| 手势 | 原生级双指缩放、旋转、倾斜 | 轨迹抖动、漂移 |
| 服务 | 内置定位辅助、坐标转换、地理编码、路线规划、POI | **GPS 精度** |
| 合规 | 有 key、有域名白名单、可商用 | 后台/锁屏持续定位（Web 仍然不行） |
| 开发 | 少写底图/坐标系代码 | 多一套 key/security/域名配置，包体更大 |

一句话：**换 SDK 解决的是"好看、好操作、合规"，不解决"准"。**

轨迹不准的原因在采集和算法：采样噪声、城市多径、暂停恢复、后台计时、滤波阈值。这些换哪个地图引擎都一样。

先分清你的不满是哪一种：

- **"地图糊、丑、加载慢、手势别扭"** → 换高德 JS API 2.0（或至少修 retina/瓦片/样式）有用。
- **"距离不准、轨迹飘、暂停后乱、切后台丢"** → 换 SDK 没用，先修第 1 节的 bug 和第 3 节的滤波。

这两类问题经常被混为一谈，最后花两天换 SDK，发现距离还是飘。

### 0.3 分场景结论

| 场景 | 推荐 | 理由 |
|---|---|---|
| **课程答辩 / 局域网手机演示** | **保持 Leaflet + 高德瓦片，先修 bug** | 无 key、无域名、断网可降级；换 SDK 只会增加现场翻车点 |
| **Web / PWA 产品（国内）** | **高德 JS API 2.0** | 矢量底图、手势、定位辅助、坐标转换、合规，国内最稳 |
| **打包成 App** | **原生高德/百度 SDK + 原生后台定位** | 锁屏/后台、传感器融合、权限管理，Web 做不到 |
| **微信小程序** | 腾讯地图组件 / 高德小程序 SDK | 原生地图组件、审核友好 |
| **海外** | MapLibre GL JS + OSM/MapTiler | 数据覆盖和合规，国内不适用 |

### 0.4 给提建议的人一句话

> "换高德/百度 SDK 我同意长期做，但它解决的是底图和手势，不是轨迹准不准。我现在距离飘，主要是滤波、暂停恢复、后台计时的问题；先把这些修了，再换 SDK 才有意义。"

### 0.5 一分钟自检（先确认问题在哪）

| 动作 | 如果出现 | 对应 bug |
|---|---|---|
| 在操场走 100m，看地图有没有画线 | 数字在动、地图"暂无轨迹" | 1.1 watcher 不触发 |
| 在非上海的城市打开跑步页 | 空地图是上海，第一个点不居中 | 1.2 首点不 fit |
| 暂停 30 秒，走 50m，再继续 | 距离一下涨了 50m / 出现直线 | 1.3 暂停锚点 |
| 切到微信 30 秒再回来 | 时长一下涨 30 秒，配速变了 | 1.4 后台计时 |
| 断网保存，然后关页 | 记录丢失；或重试后出现两条 | 1.5 无草稿/幂等 |
| 看报告页的分段 | 每段配速完全一样 | 演示数据匀速，或分段算法退化 |

## 1. 先修 6 个 bug（否则换什么地图都一样）

### 1.1 实时轨迹可能根本不刷新（最严重）

**代码**：`TrackMap.vue:205-208`

```ts
watch(() => props.points, (_n, o) => {
  const first = !o || o.length === 0
  redraw(first)
}, { deep: false })
```

**事实**：Vue 3.5 下，数组 `push` 不会触发这个 watcher。我用最小用例验证过：`watch(() => arr, cb, { deep:false })` 在 `arr.push()` 后触发 **0 次**；`watch(() => arr.length, cb)` 触发 **1 次**。

**现象**：跑步页距离/时长在动，地图一直"暂无轨迹"或不更新；报告页是静态加载，所以正常。

> 如果你们现场跑过、地图确实画出了线，说明当时跑的不是这份代码（运动模块这些文件目前都还没进 git，无法用提交历史对照）。先用下面的自检验证当前版本。

**修法**：监听长度，增量追加：

```ts
watch(() => props.points.length, (len, prev) => {
  if (len === 0) { clearAll(); return }
  if (len === 1) { map.setView(toLatLng(props.points[0]), 17); return }
  if (len < prev) { redrawAll(); return }        // 重置/回放
  line?.addLatLng(toLatLng(props.points[len - 1]))
  updateLiveDot(toLatLng(props.points[len - 1]))
})
```

不要用 `deep: true`（每个点全量遍历），也不要在父组件每个点替换数组（O(n) 拷贝）。

**自检**：跑 100m，如果地图数字在动但轨迹不画，就是这条。

### 1.2 第一个点不 fit，地图停在上海

**代码**：`TrackMap.vue:89` `setView([31.2304, 121.4737], 15)`；`redraw` 的 `fit` 只在第一次调用时为 `true`。

**现象**：在别的城市跑步，空地图是上海；第一个点来了也不居中；轨迹可能画在屏幕外。

**修法**：
- `len === 1` 时 `setView(point, 17)`；
- 结束时 `fitBounds` 到整条轨迹；
- 用户手动拖动后不要抢镜头（见 4.4 的 follow 开关）。

### 1.3 暂停后恢复，距离会跨过暂停段

**代码**：`location.ts:128-156`。暂停时 `onPosition` 直接 `return`；恢复时 `arr[arr.length-1]` 还是暂停前的点。

**现象**：暂停期间走了 100m，恢复后：
- 第一个点 `dt ≈ 0` → 被丢；
- 下一个点可能因速度突变被丢；
- 再下一个点通过，但距离从**暂停前的点**直接连过来 → 暂停期间的路程被算进去，地图上出现一条直线。

**修法**：

```ts
let skipNext = false
function resume() {
  if (state.value !== 'paused') return
  skipNext = true
  lastTick = performance.now()
  state.value = 'running'
}
function onPosition(pos) {
  ...
  if (skipNext) { anchor = p; skipNext = false; return }  // 只更新基准点，不加距离
}
```

或者把轨迹按"段"存：暂停/后台/隧道处断开，段与段之间不累加距离。

### 1.4 切后台回来，计时会跳

**代码**：`location.ts:92-101`，`setInterval(200ms)` 累加 `elapsedSec`；浏览器对后台 tab 会节流。

**现象**：切出去 60 秒，回来 `elapsedSec` 一下加 60 秒，但轨迹没有这 60 秒的点，配速被拉低/拉高。

**修法**：
- `visibilitychange` 时记 `hiddenAt`；
- 回来如果 `dt > 5s`，这段标为 gap：不计时、不计距离，提示"后台期间未记录"；
- `setInterval` 的 `dt` 上限设 2 秒，避免大跳；
- 页面隐藏时 `wakeLock` 会被释放，回来要重新 `request`；
- iOS 可能停掉 `watchPosition`，回来要重建 watch。

### 1.5 保存失败/重复提交

**代码**：`RunTrackView.vue:96-120`，`lastResult` 只在内存；`createWorkout` 没有幂等键。

**现象**：
- 保存失败关页就丢；
- 网络超时但服务端已成功，用户点"重新保存"生成第二条。

**修法**：
- IndexedDB 草稿：每 5 秒写一次，重进页面提示"发现未完成的跑步，恢复？"；
- 每次开始生成 `client_id`（UUID），随请求提交，后端唯一索引，重试幂等；
- `beforeunload` 拦不住 SPA 路由返回，用 `onBeforeRouteLeave` 再加一道。

### 1.6 时长仍信前端（数据可信）

**代码**：`workouts.py:161`

```python
duration_sec = data.duration_sec or stats["duration_sec"]
```

有轨迹时应该以 `track[-1].t` 为准，否则提交 1 秒 + 5km 轨迹，配速/消耗全错，"服务端重算"的口径不成立。

```python
if kept:
    duration_sec = int(round(kept[-1]["t"]))
```

## 2. 地图方案对比

| 方案 | key/合规 | 底图质量 | 手势 | 首屏/包体 | 离线/降级 | 定位辅助 | 坐标 | 适合 |
|---|---|---|---|---|---|---|---|---|
| **Leaflet + 高德瓦片（现状）** | 无 key；瓦片端点非官方 | 栅格，够用；高 DPI 会糊 | 够用，惯性/双指 | 轻，~40KB | 可降级网格 | 无，靠浏览器 | 自己转 GCJ-02 | 课程演示、快速原型 |
| **高德 JS API 2.0** | key + `securityJsCode` + 域名白名单 | 矢量，清晰、可换样式 | 原生级，平滑 | SDK 几百 KB | 断网白屏，需自己做兜底 | 有 `AMap.Geolocation` | GCJ-02 | Web/PWA 产品 |
| **百度 BMapGL** | `ak` | 矢量，POI 强 | 好 | 几百 KB | 同上 | 有 | **BD-09**，多一步转换 | 已有百度生态 |
| **腾讯 JS API GL** | key | 矢量 | 好 | 几百 KB | 同上 | 有 | GCJ-02 | 微信生态 |
| **MapLibre + OSM/MapTiler** | 需要 tile 服务 | 矢量 | 好 | 中等 | 可自托管 | 无 | WGS-84 | 海外/自托管 |
| **原生高德/百度 SDK** | key + 签名 | 最好 | 最好 | 只 App | 可缓存 | 传感器融合 | GCJ-02/BD-09 | 打包 App |

### 2.1 为什么课程阶段不建议换

- **现场风险**：key 要配 `securityJsCode`、域名白名单；教室网络/手机热点一变，地图可能直接白屏。Leaflet 至少能降级成网格。
- **收益不对等**：换 SDK 主要提升"底图好看/手势顺"，评委更在意"轨迹准不准、数据说不说得清"。
- **工作量**：接入、坐标系、polyline、marker、定位、样式，至少 1–2 天，且要重新测。
- **不解决核心问题**：1.1–1.6 的 bug 换 SDK 也还在。

### 2.2 什么时候该换

- 你要做 **Web/PWA 上线**：换高德 JS API 2.0。它是国内 Web 地图里最适合跑步场景的：矢量底图、户外样式、`AMap.Geolocation`、`AMap.Polyline`（`showDir` 画方向）、`AMap.Marker`、`AMap.MoveAnimation`（轨迹回放）。
- 你要 **打包 App**：换原生高德/百度 SDK + 后台定位。这是唯一能解决"锁屏/后台"的路径。
- 你要 **微信小程序**：腾讯地图组件，别用 Web 方案硬套。

### 2.3 高德/百度怎么选

- **跑步/骑行/户外**：优先高德。户外样式更干净，国内跑步类 App 用得多，GCJ-02 和现在代码一致。
- **百度**：BMapGL 技术上不差，但坐标是 BD-09，多一层转换；除非团队已有百度 key/经验，或者你需要百度的 POI，否则没有明显优势。
- **腾讯**：微信小程序首选；纯 Web 跑步场景不如高德。
- **MapLibre/OSM**：国内路网和 POI 覆盖不足，跑步轨迹底图会很空，不建议。

### 2.4 换高德 JS API 的迁移清单（如果决定换）

1. 申请 key + `securityJsCode`，配域名白名单；生产环境 `securityJsCode` 走后端代理，不要直接放前端。
2. 保持 **WGS-84 为唯一存储坐标**；只在渲染层转 GCJ-02（现在就是这么做的）。
3. `AMap.Map` + `viewMode: '2D'` + 自定义 `mapStyle`（户外/浅色）。
4. `AMap.Polyline`：`showDir: true`、`strokeWeight: 5`、`strokeColor` 按配速分段。
5. `AMap.Marker`：起点/终点/公里牌；`AMap.Circle`：精度圈。
6. `AMap.Geolocation`：只用于**首点/辅助定位**；连续轨迹仍建议 `navigator.geolocation.watchPosition`，避免两套坐标源混用。
7. 断网兜底：SDK 白屏时显示网格 + "底图加载失败，轨迹仍可查看"，并给"重试"。
8. 回归测试：1.1–1.6 的用例全部重跑。

## 3. 定位精度：怎么做才准

### 3.1 误差从哪来

- **天空视野**：高楼、树荫、隧道、地下车库；
- **多径反射**：城市峡谷，GPS 信号反射，位置跳几十米；
- **冷启动**：第一次定位可能用基站/WiFi，精度差；
- **省电模式**：iOS 低电量、Android 省电会降频/关高精度；
- **浏览器节流**：后台 tab 不给定位；
- **坐标系**：WGS-84/GCJ-02 不转，整体偏几百米（你们已经处理）。

### 3.2 SDK 能做什么、不能做什么

- `AMap.Geolocation` 能：首点更快（网络定位辅助）、室内/城市初定位更稳、返回精度半径。
- 不能：让连续跑步轨迹变准。跑动中的每个点还是设备 GPS 给的，噪声还在。
- 原生 SDK 能：传感器融合（加速度计/陀螺仪）、后台持续定位、系统级省电策略；这是 App 阶段的事。

### 3.3 采集与滤波（重点）

**a. 预热**
不要拿到第一个点就开跑。先收集 3–5 个点，等 `accuracy <= 15m` 且稳定，再 3-2-1 倒计时。否则前 10 秒全是垃圾点。

**b. 采样**
`watchPosition`：`enableHighAccuracy: true`、`maximumAge: 0`、`timeout: 10000`。1Hz 足够，别追求 10Hz。

**c. 过滤（替换现在的固定阈值）**

现在：`accuracy > 35m` 丢、位移 `< 3m` 丢、速度 `> 12m/s` 丢。
问题：3m 对 10m 精度的 GPS 来说太低，站着不动也会累计几米；35m 硬丢又会把城市里的点丢光。

建议：

```ts
const acc = pos.coords.accuracy ?? 50
if (acc > 50) return                         // 太差，直接丢
const minMove = Math.max(2.5, Math.min(8, acc * 0.4))
if (d < minMove) return                      // 抖动/站立
if (v > 12) return                           // 瞬移
if (d > 100 && dt < 2) return                // 2 秒跳 100m，必是漂移
```

**d. 平滑**
简单 EMA：`lat = lat * 0.7 + newLat * 0.3`；更好的是匀速 Kalman（状态 `[lat, lng, vx, vy]`），大约 50 行。课程项目用 EMA + 自适应阈值就够；产品再上 Kalman。

**e. 距离**
在**平滑后的点**上累加，不要用原始点。原始点只存下来做审计/回放。

**f. 自动暂停**
速度 `< 0.5 m/s` 持续 15–20 秒 → 自动暂停；`> 1.0 m/s` 持续 3 秒 → 恢复。等红灯、系鞋带不再污染配速。做成可开关。

**g. 分段**
暂停、后台、隧道、定位丢失 > 30 秒，都断开成新段；**段与段之间不累加距离**，不要把 gap 连成直线。

**h. 服务端重算**
- 时长从 `track[-1].t` 推；
- 校验平均速度在 0.5–12 m/s；
- 存 `point_count`、`avg_accuracy`、`max_gap_sec`；
- 展示用 Douglas-Peucker 抽稀到 600–800 点，统计用原始累加值。

**i. 置信度**
报告页标"GPS 精度 ±8m，距离误差约 2%"或"信号弱，距离可能偏差"。不要假装精确到 0.01km。

### 3.4 一个可用的伪代码

```ts
onPosition(pos) {
  const acc = pos.coords.accuracy ?? 99
  if (acc > 50) return

  const p = { lat: pos.coords.latitude, lng: pos.coords.longitude, t: elapsed, acc }
  if (!anchor) { anchor = p; push(p); return }

  const d = haversine(anchor, p)
  const dt = p.t - anchor.t
  if (dt <= 0) return

  const v = d / dt
  const minMove = Math.max(2.5, Math.min(8, acc * 0.4))
  if (d < minMove) return
  if (v > 12) return
  if (d > 100 && dt < 2) return

  const s = smooth(p)           // EMA / Kalman
  distance += haversine(lastSmooth, s)
  lastSmooth = s
  anchor = p
  push(s)
}
```

### 3.5 测试矩阵

| 场景 | 方法 | 通过标准 |
|---|---|---|
| 400m 标准跑道 | 跑 2 圈，对比已知 800m | 开阔地误差 < 3% |
| 城市街道 | 1km 直线，楼间 | 误差 < 8%，无 50m 以上跳点 |
| 原地站立 2 分钟 | 不动 | 累计距离 < 20m |
| 暂停 1 分钟再走 | 暂停期间移动 100m | 恢复后距离不包含这 100m，无直线 |
| 切后台 1 分钟 | 锁屏/切应用 | 显示 gap，不产生假距离，计时不跳 |
| 隧道 30 秒 | 进隧道再出 | 断开分段，不画穿墙直线 |
| 瓦片失败 | 断网/改 tile URL | 网格 + 轨迹可见，不白屏 |
| 保存失败 | 断网保存 | 草稿可恢复，重试不重复 |

## 4. 地图渲染：怎么做得像 Keep

### 4.1 轨迹

- **增量追加**：`line.addLatLng()`，不要每秒 `setLatLngs(全部点)`。
- **按配速分段着色**：快/正常/慢三色；每公里或每 N 个点切一段；段数控制在 50 以内，避免 polyline 太多。
- **白色描边**：先画一条 7px 白线，再画 5px 绿线，轨迹在浅色底图上更清楚。
- **起终点**：绿点"起"、红点"终"，用 `divIcon` 带文字。
- **公里牌**：每公里一个 `divIcon`（`1km`、`2km`），位置用线性插值。
- **方向箭头**：Leaflet 用 `leaflet-polylinedecorator`；高德用 `showDir: true`。跑动中能看出方向。
- **精度圈**：`L.circle(last, { radius: accuracy })`，只在 `accuracy > 15m` 时显示，让用户知道"现在信号一般"。

### 4.2 视野与跟随

- 第一个点：`setView(point, 17)`。
- 跑动中：`panTo` 每 3–5 秒一次，别每点都动。
- **follow 开关**：用户手动拖动/缩放后自动关掉跟随，显示"回到当前位置"按钮；否则地图一直抢镜头，体验很差。
- 结束：`fitBounds` 到整条轨迹，留 26px padding。
- 桌面演示：加 `L.control.zoom` 和 `L.control.scale`；手机端可以隐藏 zoom 控件。

### 4.3 瓦片与加载

- `detectRetina: true`（如果高德瓦片支持 @2x；不支持就保持 256，至少别强制放大）。
- `maxNativeZoom: 18`、`maxZoom: 19`，避免 z19 请求 404 白块。
- `keepBuffer: 4`、`updateWhenIdle: false`，减少拖动白屏。
- **加载状态**：`tileloadstart` / `tileload` / `tileerror` 计数，显示 skeleton 或"地图加载中"。
- **失败兜底**：连续失败且 0 成功 → 移除 tileLayer，显示网格 + "底图加载失败，轨迹仍可查看" + 重试按钮；不要让失败的 layer 一直请求。
- **离线演示**：把答辩场地周边 z14–18 的瓦片预下载到 `public/tiles`，用本地 tileLayer；没有网络也能显示底图。这是课程演示最稳的方案。

### 4.4 视觉

- 跑步页是深色，地图是亮色，夜里刺眼；可以给瓦片加轻微暗色滤镜，或做日/夜两套。
- 轨迹绿色 `#22c55e` 和页面按钮 `#67c23a` 不统一；选一个主色。
- 地图圆角、阴影、attribution 弱化，保持和 App 其他卡片一致。
- 不要把"© 高德地图"删掉；课程项目也要保留 attribution。

### 4.5 性能

- `preferCanvas: true` 已开，保留。
- 重绘节流到 1Hz；点数 > 2000 时，显示用抽稀点。
- 不在 `watch` 里做深拷贝/全量遍历。
- 地图容器用 `ResizeObserver` + `invalidateSize`，避免旋转屏后错位。

## 5. 录制流程与状态机

### 5.1 状态

```
idle → preparing（权限 + 首点 + 预热 + 倒计时）→ recording ⇄ paused → finishing → saved | discarded
```

| 状态 | 允许操作 | 说明 |
|---|---|---|
| idle | 开始 | 未定位 |
| preparing | 取消 | 申请权限、等 3–5 个好点、3-2-1 |
| recording | 暂停、长按结束 | 计时/计距 |
| paused | 继续、结束 | 不计时/不计距，锚点断开 |
| finishing | 保存/放弃 | 防重复提交 |
| saved | 看报告 | 清草稿 |
| discarded | 返回 | 清草稿 |

### 5.2 必须有的交互

- **3-2-1 倒计时**：点开始后，手机还没放进口袋的 10 秒不算。
- **目标跑**（可选）：3/5/10km 或 20/30/60min，进度环 + 到点语音。
- **自动暂停**（可选）：等红灯不污染配速。
- **语音播报**：每公里 + 每 5 分钟；`speechSynthesis` 免费。
- **长按结束 + 环形进度**：800ms 只有颜色变化不够，用户不知道要按多久。
- **太短不劝退**：`< 100m / < 1min` 提示"本次太短，是否保存"，默认"保存"，别默认"放弃"。
- **保存失败可恢复**：草稿 + 重试 + 幂等。
- **后台提示**：切后台前提示"会中断记录"；回来显示 gap。
- **屏幕常亮**：WakeLock + 重新申请。
- **锁屏/后台**：Web 做不到，明确告诉用户；App 阶段用原生。

### 5.3 草稿与恢复

- 每 5 秒写 IndexedDB：`{ clientId, startAt, sport, points, state, elapsed }`。
- 进入跑步页时检查草稿：有则弹"恢复上次记录？"。
- 保存成功/主动放弃后清草稿。
- `clientId` 用于后端幂等：`UNIQUE(user_id, client_id)`。

### 5.4 防误触与路由

- 长按结束 + 二次确认。
- `onBeforeRouteLeave` 拦截 SPA 返回；`beforeunload` 拦截关页。
- 保存中禁用返回/结束按钮。

## 6. 报告页（模块内）

- **地图**：`fitBounds` 整条轨迹；公里牌；配速着色；起终点；可选回放（按 `t` 逐点画）。
- **四个数**：距离、时长、平均配速/均速、消耗。骑行必须显示 **km/h**，不是配速。
- **分段**：每公里配速条 + 最快公里；最后一截标"部分"。
- **心率**：没有就整块隐藏，不要显示"--"。
- **数据来源**：手机定位 / 手环 / 手动 / 跟练 + 轨迹点数 + 平均精度。
- **对比**：和上次同类型比（"比上次快 12 秒"），这是模块内就能做的，不需要社区。
- **分享**：轨迹水印海报；导出 GPX。
- **删除**：二次确认；明确说"当天的运动记录也会移除"。

## 7. 验收标准

| 项 | 标准 |
|---|---|
| 实时轨迹 | 跑 100m，地图连续画线，无"暂无轨迹" |
| 首点定位 | 进入页面 3–8 秒内居中到当前位置 |
| 距离 | 400m 跑道误差 < 3%（开阔地）；城市 < 8% |
| 静止 | 原地 2 分钟，累计 < 20m |
| 暂停 | 暂停期间移动不计距离，恢复无直线 |
| 后台 | 切后台 1 分钟，回来显示 gap，计时不跳 |
| 瓦片失败 | 网格 + 轨迹可见，不白屏，可重试 |
| 保存失败 | 草稿恢复，重试不重复 |
| 性能 | 10km/1 小时，地图不卡死，内存不爆 |
| 坐标 | 轨迹不偏移到隔壁街区/楼顶 |

## 9. 结论

- **地图是显示层，定位是采集层。别用显示层解决采集层的问题。**
- 现在的地图方案（Leaflet + 高德瓦片）对课程演示是合适的；换高德/百度 SDK 的收益主要是底图和手势，不是精度。
- 真正该先做的是：实时轨迹刷新、首点 fit、暂停锚点、后台计时、草稿/幂等、时长以轨迹为准。
- 产品化再换高德 JS API 2.0；打包 App 再上原生 SDK + 后台定位。
- 汇报口径改成"Leaflet 承载高德瓦片 + Canvas 画轨迹"，别说"Canvas 拼瓦片"。
