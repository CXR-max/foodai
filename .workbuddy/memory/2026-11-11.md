## 对标 Keep 的手机端功能改造清单（文档）

- 产出：`docs/keep-benchmark-mobile.md`
- 现状结论：项目是 Vue3 + Element Plus 响应式 Web（非原生 App），已有「吃」的完整闭环（识别→AI方案→打卡→积分→商城→成就），运动只有打卡页底部的手动表单 + MET 估算；无 GPS/轨迹、课程跟练、社区、挑战赛、步数/饮水/睡眠。
- 建议分层：P0 运动模块真实化（GPS 跑步+轨迹地图+运动记录+独立运动 tab，1–2 周）；P1 内容化（课程跟练用计时器+Web Speech 语音、食物库手动搜索、body_metrics）；P2 社区/挑战/多维排行榜。
- 手机端专项：底部导航重构为「首页/运动/记录/社区/我的」，中间凸起 + 号；el-calendar/el-table/el-dialog 换移动端卡片与底部抽屉；补下拉刷新、骨架屏、图片压缩、PWA。
- 统一约定：所有新模块必须回写积分/成就/排行榜，避免数据体系分裂。

## Keep 运动记录板块流程拆解

- 产出：`docs/keep-workout-module-breakdown.md`
- 核心认知：Keep 的"选运动类型"= 选一套数据采集规则（是否开 GPS、什么指标、是否分段），不是选图标。类型分三档：A 户外定位（跑步/骑行/行走）、B 室内计量（跑步机/跳绳）、C 内容跟练（课程）。
- 流程 6 阶段：准备(搜星/模式/设置/倒计时) → 运动中(采样/点过滤/累加/分段/滑动窗口配速/语音/本地草稿) → 结束(校验/感受/服务端重算) → 报告(轨迹+数据网格+配速心率海拔图+对比) → 沉淀(历史/周月统计/日历) → 联动(打卡/积分/成就/挑战/社区/热量缺口)。
- 状态机：idle → preparing → running ⇄ paused → finishing → saved|discarded；计时用累计运行毫秒，不能用 Date.now 差值。
- 落地分三版：MVP 3~4 天（跑步+行走、开始暂停结束、单色轨迹、4 项报告）；V1 +1 周（目标跑/自动暂停/分段/speechSynthesis 语音/历史统计/打卡联动）；V2 骑行与室内跑。
- 坑：Web 无后台定位、室内跑不能依赖 GPS、距离必须服务端重算、消耗走现有 MET 模型、轨迹需抽稀、禁止实时上传。

## 转 App 前的改造流程（待组长确认，未改代码）

- 产出：`docs/app-packaging-workout-plan.md`
- 关键事实（已核对代码）：
  - `frontend/src/api/http.ts` 已支持 `VITE_API_BASE` 与 `assetUrl`，打包后接口/图片地址这层已有口子。
  - `backend/app/main.py` CORS 只放行 `localhost:5173`，Capacitor 的 `capacitor://localhost` 会被拦，打包当天会白屏。
  - 后端有 `auto_fix_columns()` 启动补列 hack，新表建议走 alembic（versions 已有 8 个）。
  - 仓库内无 device/band/import 相关表与接口，手环数据仍停留在组员本地脚本。
- 结论："打包后不能改"半对：后端随时改；前端改界面要重新打包分发；原生权限/插件必须重新打包；旧版不会自动更新。真正不能后改的是数据结构。
- 建议顺序：S0 地基（platform 适配层 + workouts/body_metrics/data_imports 三表 + CORS/HTTPS，3~5 天）→ S1 手环导入（统一 schema + 幂等导入接口 + 通用导入页 + 心率与跑步合并，3~4 天）→ S2 运动模块 → S3 内容跟练 → S4 界面移动化。
- 手环数据没有 GPS 轨迹（只有时长/心率/消耗/睡眠/步数），轨迹必须靠手机定位，两者互补。
- 待确认：打包方式（推荐 Capacitor）、打包时间点、打包后能否重新打包、手环样本文件、是否做心率。

## 补充：底图换高德 + 手机视口截图能力

- `TrackMap.vue` 瓦片源默认从 OSM 改为**高德**（`webrd0{s}.is.autonavi.com/appmaptile?...style=8`，免 key 国内可直连）；OSM/天地图(无key)/GitHub 在本机网络下均不通，高德返回 200
- 关键：高德瓦片是 **GCJ-02** 坐标系，GPS 是 WGS-84，已内置 `wgs84ToGcj02()` 转换（否则轨迹整体偏移几百米）；`USE_GCJ` 按瓦片域名自动判断；支持 `{s}` 子域随机；版权文字随源切换
- 新增 `frontend/scripts/shot.cjs`：puppeteer-core + 本机 Edge（`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`），390×844/DPR2/mobile 视口，注入 localStorage.token 免登录，截图输出 `docs/screenshots/`
- 踩坑：① 跑步页有退出拦截，截图必须放最后，否则后续 goto 挂起；② 打卡页有持续请求，`networkidle2` 等不到，改用 `domcontentloaded` + 固定延时
- 演示数据：demo_xiaoming(id=1) 插入 2 条 workout（3.36km 今天 / 5.32km 3天前），走真实接口，连带产生打卡与 +2 积分
- 网络结论：localhost.run 免费隧道限速仅 2~3KB/s（element-plus.js 175KB 下不完）→ 手机白屏；局域网 8080 探针一条请求都收不到，phone→PC 的 TCP 未发出，怀疑小米自带浏览器省流代理，未最终确认
